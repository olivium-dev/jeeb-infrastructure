## What it is

For each piece of state Jeeb persists, the register records who *should* own it.
Every point is answered against the same four escalation questions, in order:

1. Is there an existing **Jeeb** microservice that can handle this case?
2. Is there another **Olivium** microservice that can?
3. Can an existing service be extended while staying Jeeb-agnostic and reusable?
4. As a last resort, is a **new repository** required?

Outcome: `new_repositories_required: 0`.

## Architecture rules asserted by the review

- The gateway is a stateless BFF with no Postgres connection or durable state.
- UPG is not used by Jeeb.
- Shared microservices must remain Jeeb-domain-agnostic.
- Extensions must be additive and backward-compatible unless separately approved.
- All wallet value changes are performed through wallet transactions.
- No new repository is currently required.

## Current vs target state

| Property | Current | Target |
| --- | --- | --- |
| Gateway has a database | true | false |
| Gateway has durable state | true | false |
| UPG used by Jeeb | branch-dependent | false |

The first two rows are the review's central finding: the gateway is **not** the
stateless BFF the rules assert, and the register is the plan for getting there.

## Reading it

Each entry in `points[]` carries `current_data` (tables + surface),
`investigation_answers` (q1–q4), `review_comment`, `review_status` and
`final_answer`. Point ids are stable — cite them as `arch-review#<id>`.

```sh
jq -r '.points[] | "\(.number)\t\(.id)\t\(.review_status)"' jeeb-architecture-review-export.json
jq '.points[] | select(.review_status != "approved")' jeeb-architecture-review-export.json
```

## Caveats

- This is a **point-in-time export** (2026-08-10), not a live view. It is not
  regenerated by CI and will drift as the services change.
- Three points (`settlement-batches`, `settlement-ledger`, `wallet-direct-read`)
  have no explicit review comment and are still owner-gated.
- The register is a *design* register. It records intended ownership, not what is
  deployed today; several points describe the target, not the live topology.
